# Sentinel Screen Catalog

Status: Draft v1.0
Last updated: 2026-08-06

## Purpose
Define the platform experience before implementation so every application shares one consistent navigation model, permission model, and interaction pattern.

## Design Rules
Every screen must define:
- Primary user role
- Business purpose
- Core entities involved
- Required permissions
- Key actions and buttons
- Offline or mobile support expectations
- AI assistance expectations

## Screen Design Standard
Each screen should support:
- Search and filter
- Activity history
- Related entity drill-down
- Role-aware actions
- Audit trail visibility
- Export and print options
- Mobile-first as needed

## Approval Checklist
- Core screens defined for each application
- Navigation hierarchy reviewed
- Permission-sensitive actions documented
- Offline behavior defined for field workflows
- AI entry points identified
