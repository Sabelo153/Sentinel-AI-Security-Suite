# Sentinel Design System

Status: Draft v1.0
Last updated: 2026-08-06

## Purpose
Define the shared visual language and component system for Sentinel so all applications, platforms, and screens feel consistent.

## Design Principles
- Consistent, enterprise-grade, and calm
- Optimized for operational speed and clarity
- Accessible for desktop, tablet, and mobile use
- Designed for security, compliance, and trust
- Suitable for BAC and Sentinel branding

## Typography
- Primary font: Inter or similar clean sans-serif
- Heading scale: clear hierarchy for dashboards, forms, tables, and alerts
- Body text: optimized for readability and dense operational information
- Use strong contrast and concise labels

## Color System
- Primary: deep blue / security-focused brand tone
- Accent: amber or warning color for high-risk actions
- Success: green for approved or healthy states
- Error: red for critical alerts and failures
- Neutral: gray tones for supporting UI and dividers

## Icon System
- Use a consistent icon set for operations, HR, finance, fleet, assets, AI, reports, and administration
- Icons must be clear, simple, and recognizable at small sizes
- Use semantic icons for status, warning, approval, and exception states

## Core Components

### Buttons
- Primary: main actions such as Save, Submit, Approve
- Secondary: cancel, back, close
- Tertiary: low-priority actions
- Destructive: delete, archive, revoke

### Cards
- Use cards for summaries, metrics, status blocks, and quick views
- Cards should support compact and full-detail layouts

### Tables
- Support sorting, filtering, paging, and row selection
- Use consistent row states for active, warning, error, and archived records
- Provide dense and comfortable table modes

### Forms
- Group fields by logical sections
- Show inline validation and helper text
- Keep critical actions visible and near the form footer
- Support required/optional states clearly

### Modals and Panels
- Use for focused tasks and quick edits
- Keep actions predictable and within a single workflow
- Support keyboard navigation and focus management

### Alerts and Notifications
- Informational, warning, success, and critical states
- Keep messages concise and actionable
- Provide clear dismissal and follow-up actions

### Charts and Data Visuals
- Favor simple KPI charts, trend charts, and heatmaps
- Use consistent colors and legends
- Provide accessible labels and data tables where necessary

## Layout Rules
- Use consistent spacing and grid systems across all surfaces
- Dashboard layouts should prioritize summary, exception, and action
- Table-first layouts for operations lists
- Detail-first layouts for profile and workflow screens

## Mobile Components
- Touch-friendly controls
- Bottom-sheet style actions where appropriate
- Compact form elements and bio-friendly layouts
- Offline and sync status indicators

## Desktop Components
- Multi-panel layouts for operations oversight
- Keyboard shortcuts for power users
- Advanced filtering and bulk actions

## Accessibility Requirements
- WCAG-compatible contrast and keyboard support
- Screen-reader-friendly labels and ARIA semantics where applicable
- Focus states must be visible for interactive elements
- Error and success states must be understandable without color alone

## Dark Mode
- Support a dark theme for control-room and extended-use environments
- Ensure contrast and readability remain consistent

## Branding Rules
- Preserve BAC / Sentinel brand identity in a professional enterprise tone
- Use the same navigation, component language, and spacing across all products

## Approval Checklist
- Typography system approved
- Color system approved
- Component inventory agreed
- Accessibility and mobile standards approved
- Brand usage rules documented
